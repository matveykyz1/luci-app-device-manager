# luci-app-device-manager

Менеджер зарегистрированных устройств для LuCI: **Сеть → Устройства**. Пакет рассчитан на OpenWrt 25.12 с `firewall4`, `rpcd` и современным JavaScript LuCI. Код интерфейса использует `_()` для будущих переводов; исходные строки интерфейса русские.

## Проверенная исходная платформа

Локальное дерево проекта SRX5308 содержит OpenWrt **25.12-SNAPSHOT**, Linux **6.12.112**, архитектуру **mips64_octeonplus**, LuCI из commit `75a306d` (собранный `luci-base-26.288.56989~75a306d`) и менеджер пакетов **apk**. У платы один Cavium CN5010, по раннему аппаратному журналу `MemTotal` 417704 кБ; Flash 64 МиБ, записываемый overlay около 16,5 МиБ. Эти сведения относятся к имеющимся исходникам и журналам, а не к новому сеансу диагностики работающего роутера.

Исходная конфигурация платы создаёт `br-lan` на `lan1`–`lan4`, WAN на `wan1`, дополнительные `wan2`–`wan4` в зоне `wan`; IPv6 в конкретном профиле SRX5308 изначально отключён. В журнале ранее наблюдались `10.0.0.0/24` как временная LAN-подсеть и `192.168.1.0/24` как последующая LAN-подсеть. Текущие DHCP/DNS, VLAN, firewall, nftables, зоны и свободное место **на живом роутере не подтверждены**: в рабочем окружении нет доступа к его shell/netlink. Приложение определяет логические сети и зоны во время работы через netifd/ubus и UCI; IoT и Guest не привязаны к имени `lan`.

## Возможности

- Обнаружение из dnsmasq DHCPv4 аренды, статических DHCP-записей, odhcpd DHCPv6 при наличии ubus-метода, IPv4/IPv6 соседей, bridge FDB и hostapd.
- Разделение DHCP hostname, DNS hostname и пользовательского названия. Регистрация по MAC, ручное добавление, отдельные незарегистрированные устройства. IP при регистрации не закрепляется.
- Отдельные списки зарегистрированных и незарегистрированных устройств. Нажатие на запись незарегистрированного клиента открывает простую форму регистрации; запись зарегистрированного клиента открывает карточку настроек. Есть поиск, сортировка, фильтры, выбор всех видимых устройств, снятие выбора, массовые действия и обновление каждые 15 секунд. На узких экранах записи показываются карточками.
- Блокировка маршрутизируемого трафика к интерфейсам указанной интернет-зоны через отдельную цепочку nftables `inet fw4`. Работает для IPv4 и IPv6, если IPv6 включён на устройстве. Доступ к самому роутеру не затрагивается.
- Количество заблокированных показывает устройства, MAC которых найден в действующей nft-цепочке приложения; при недоступной проверке интерфейс сообщает о неизвестном статусе.
- Расписание разрешённого интернета по системному часовому поясу. Монитор сверяет состояние каждые 30 секунд. `fw4` включает сохранённый файл правил после перезапуска firewall; монитор пересчитывает расписание после загрузки/перезапуска.
- Группы, массовая регистрация, блокировка, разблокировка, назначение группы и расписания.
- Экспорт и импорт JSON с проверкой версии, MAC, расписаний, групп и дубликатов.
- Счётчики принятого/отправленного трафика текущего периода `nlbwmon`, если он установлен. Установка `nlbwmon` необязательна.

## Ограничения, которые видны пользователю

- DHCP-аренда, статическая запись и старая FDB/ARP-запись **не доказывают онлайн**. Онлайн означает актуальную `REACHABLE`/`DELAY`/`PROBE` соседскую запись либо аутентифицированную ассоциацию hostapd. Пассивный клиент без этих признаков может отображаться офлайн. Для DHCP-клиента приложение может определить логическую сеть по IP-подсети при однозначном совпадении с netifd; это не подтверждает физический интерфейс и не используется как основание для блокировки.
- MAC-адрес можно подменить. Устройства с приватными/рандомизированными MAC не объединяются автоматически. Для устройства без известного входящего интерфейса блокировка отклоняется. При аппаратном flow offloading блокировка также отклоняется.
- Интернет-зона по умолчанию `wan`; изменить можно через `uci set device-manager.main.internet_zone='имя_зоны'`. Доступ через другие зоны, в том числе отдельный VPN или вторую интернет-зону, этим правилом не ограничивается. Перед применением следует указать именно зону реальных внешних интерфейсов.
- Ограничение скорости отключено: в профиле не выбраны `tc`/SQM и не исследованы flow offloading и аппаратное ускорение на живом устройстве. Поля желаемой скорости можно хранить при импорте, но приложение не выдаёт их за применённое ограничение. Текущую скорость, суточную и месячную статистику приложение не показывает без достоверного источника.
- Расписание применяется с задержкой до 30 секунд на границе интервала. После перезапуска firewall сохраняется последнее записанное правило; монитор корректирует его в течение 30 секунд. Это ограничение существенно для строгого родительского контроля.
- Производитель выводится как «Неизвестно», пока нет проверенной базы OUI. DNS/DHCP конфигурация не меняется при переименовании. Статические IP не создаются автоматически.
- Реальная блокировка IPv4/IPv6, перезагрузка роутера и мобильный экран требуют испытания на устройстве. Пакет **не устанавливался** на работающий роутер.

## Хранение и безопасность

Долговременные записи находятся в `/etc/config/device-manager` (schema 1). На каждое изменение настроек сохраняются до 20 событий; время последнего обнаружения записывается во Flash не чаще раза в сутки для каждого устройства. Частые наблюдения и переходы онлайн/офлайн хранятся только в `/tmp/device-manager-sightings.json`. Файл `/etc/nftables.d/90-device-manager.nft` принадлежит приложению. Другие UCI-пакеты (`network`, `dhcp`, `firewall`) приложение читает, но не меняет. Пакет содержит минимальный ACL на собственный объект `device.manager`.

При изменении правил приложение генерирует файл, выполняет `fw4 check`, затем `fw4 reload`. При ошибке файл правил восстанавливается и firewall повторно перезагружается. Правила создаются только для зарегистрированных устройств с явной блокировкой либо активным расписанием. Глобальная политика firewall не изменяется.

Формат расписания: `1,2,3,4,5@08:00-22:00;6,7@00:00-24:00`. Цифры 1–7 означают понедельник–воскресенье; перечисленные интервалы разрешают интернет, остальное время блокируется. Интервалы не пересекают полночь: для перехода через неё задайте два интервала. `schema` другой версии отклоняется; миграция пока не нужна, так как это первая версия формата.

## Сборка

В дереве OpenWrt с подключённым LuCI feed:

```sh
ln -s /путь/к/luci-app-device-manager feeds/luci/applications/luci-app-device-manager
./scripts/feeds install -p luci luci-app-device-manager
make 'CONFIG_PACKAGE_luci-app-device-manager=m' package/feeds/luci/luci-app-device-manager/compile -j2
```

Для описанного SRX5308 результат: `bin/packages/mips64_octeonplus/luci/luci-app-device-manager-1.0.0-r7.apk`. На другой архитектуре нужно собрать пакет в соответствующем SDK/buildroot. Исходники не требуют Python или Lua на роутере. Для OpenWrt 24.10 и `opkg` нужна отдельная сборка с его LuCI/firewall4, она не проверена.

Копия собранного APK включена в `dist/luci-app-device-manager-1.0.0-r7.apk` (SHA-256: `3d191dd15cca6420cdaee5df57087093c382e04e8bdb26cbd869d3f2b531ef18`).

## Установка и удаление

Установка на роутер выполняется **только после отдельного разрешения владельца**. Для OpenWrt 25.12 скопируйте собранный APK и выполните на роутере:

```sh
apk add --allow-untrusted /tmp/luci-app-device-manager-1.0.0-r7.apk
```

Перед удалением экспортируйте реестр из интерфейса, если он нужен. Удаление:

```sh
apk del luci-app-device-manager
```

Скрипт удаления останавливает монитор, удаляет **только** `/etc/nftables.d/90-device-manager.nft` и повторно загружает firewall. Конфигурация DHCP, VLAN, WAN, VPN и сторонние правила firewall не удаляются. `/etc/config/device-manager` является conffile и может сохраниться в зависимости от режима удаления APK; при необходимости удалите его отдельно после экспорта.

## Проверки

Автоматические тесты на хосте запускаются `UCODE=/путь/к/ucode tests/test_backend.sh` и `node tests/test_ui.js`. Они используют модели UCI, ubus, сетевых источников и LuCI DOM, не обращаются к роутеру. Проверены обнаружение DHCP и клиента без DHCP, IoT-сеть, отсутствие ложного онлайн от аренды/FDB, регистрация, имя после исчезновения клиента, смена IP, формирование/удаление nft-правила, формат расписания, группы, импорт/экспорт, дубликаты, защита MAC роутера и отключённое ограничение скорости. UI-тест проверяет начальные состояния флажков, выбор всех видимых устройств, снятие выбора и отображение сохранённых настроек доступа и расписания. Синтаксис JavaScript проверен `node --check`. APK собран локальным OpenWrt buildroot и проверен `apk adbdump`.

На устройстве остаётся проверить: реальные правила IPv4 и IPv6, горячий переход расписания и рестарт firewall, перезагрузку роутера, статус Wi‑Fi и DHCPv6 на конкретной прошивке, импорт/удаление через APK, верстку на телефоне и совместимость с действующими правилами/VPN. Для SRX5308 IPv6 изначально отключён, поэтому его тест требует отдельного разрешённого окружения.

| Проверка из задания | Результат |
|---|---|
| DHCP-клиент; клиент без DHCP; несколько сетей | Локальные тесты RPC с моделируемыми DHCP, Neighbor и bridge, включая IoT и однозначное определение сети по подсети |
| Регистрация; имя; отключение; смена IP; UCI | Локальные тесты и сборка APK |
| Блокировка IPv4/IPv6; разблокировка | Генерация семейно-нейтральной цепочки `inet fw4` проверена локально; прохождение пакетов на устройстве не проверено |
| Расписание; перезапуск firewall; перезагрузка роутера | Формат и сохранение правил проверены локально; временные переходы и reboot на устройстве не проверены |
| Мобильный экран | Для узких экранов реализованы карточки устройств; браузерная проверка не проведена |
| Отсутствующие зависимости | Возможности скорости и статистики явно отключаются/объясняются; живое окружение не проверено |
| Защита административного доступа | Правило действует только на `forward`, MAC самого роутера отклоняется; аппаратная проверка не проведена |
| Удаление без нарушения чужих настроек | APK-скрипт удаляет только собственный nft-файл; фактическое удаление на устройстве не проверено |
